# CLAUDE.md — backend (NestJS API)

Read [`../CLAUDE.md`](../CLAUDE.md) first for repo-wide rules and [`../TRIAL.md`](../TRIAL.md)
before touching recommendations, trials or squads. What is implemented, and why, is in
[`README.md`](./README.md).

## 1. Architecture

**Modular monolith** on NestJS 10 + Prisma 6 + Postgres 16 + Redis 7 (README §1.15, §1.20). One
Nest module per domain: `Module` (DI) + `Service` (logic) + `Controller` (HTTP) + `dto/`
(validation). Modules talk only through exported providers.

Cross-cutting concerns are wired once in `src/app.module.ts` (`APP_GUARD` / `APP_FILTER`), so every
route gets them by default, in this order:

```
ThrottleGuard       → @Throttle(...) per-route rate limits (Redis-backed), before any auth work
JwtAuthGuard        → authenticates, or short-circuits for @Public()
RolesGuard          → @Roles(...) against the X-Active-Role the client sends
PermissionsGuard    → @RequirePermissions(...)
HttpExceptionFilter → one JSON error shape, errorId logged for 500s
```

Request flow: `main.ts` global `ValidationPipe({ whitelist, forbidNonWhitelisted, transform })` →
guards → controller → service → `PrismaService` / `RedisService` / `StorageService` → response.
Global prefix **`/api/v1`**; Swagger UI at `/docs`.

## 2. Layout

```
backend/
├── prisma/schema.prisma      # data model; migrations/ generated, never hand-edited; seed.ts bootstrap
├── openapi.json               # generated by pnpm docs:generate — commit with every route/DTO change
├── src/
│   ├── main.ts  app.module.ts  swagger.ts (API_TAGS)
│   ├── common/    decorators (@Public @Roles @RequirePermissions @CurrentUser @OptionalUser @Throttle),
│   │              guards, filters, dto/pagination.dto.ts, validators, pure utils (age, rich-text, seo)
│   ├── prisma/  redis/  audit/  storage/  email/  sms/  telegram/  rate-limit/   # infrastructure
│   ├── auth/  users/  rbac/  players/  coaches/  academies/  follows/  media/     # domain
│   ├── recommendations/  trials/  notifications/  moderation/  requests/  admin/
│   ├── insights/  tariffs/  blog/
│   └── <module>/*.util.ts       # pure, DI-free logic beside its service (unit-tested alone)
└── scripts/                    # r2 checks, docs generation
```

Naming: module dirs plural (`trials/`), `<Domain>Service` / `<Domain>Controller`,
`<Verb><Domain>Dto`, Prisma models PascalCase singular, enums SCREAMING_SNAKE values, route params
camelCase (`:academyId`).

## 3. Rules that keep the code consistent

- Services get `PrismaService` by injection (it is `@Global`); never `new PrismaClient()`.
- Controllers are thin: extract params, call one service method. Validation lives in DTOs; the
  whitelist pipe rejects unknown fields, so a field on the wrong DTO class is silently a 400.
- Current user: `@CurrentUser() user: AuthUser`. On `@Public()` routes that personalise for a
  signed-in viewer, `@OptionalUser()` — **it yields the `userId` string**, not an `AuthUser`.
- Ownership checks (`assertAcademyManager`, `ownPlayerProfile`) are private service helpers, not
  inline lookups. Role checks use the _active_ role; the API never trusts the client's menu.
- Pagination: extend `PaginationDto` (`toSkipTake`, `pageOf`) and return
  `{ items, total, page, pageSize }`.
- Media visibility is asked only through `media/media-visibility.util.ts` (`PUBLIC_MEDIA_WHERE`,
  `MODERATION_QUEUE_WHERE`): a clip is public when `moderationStatus = VERIFIED` and `status` is
  in `WATCHABLE_STATUSES` (ACTIVE, PROCESSING, FAILED). Unverified media never leaves the uploader
  and moderators. The feed's raw SQL mirrors the same predicate.
- Storage keys come from `storage/storage.keys.ts`. `public/` (avatars, academy imagery,
  `public/blog/<post>/`) is served from the CDN origin; `private/players/…` only via presigned
  URLs. `assertKeyUnder` guards every client-supplied key.
- Trials: application stages come from `trials/application-stage.util.ts`; verdicts are PASS/FAIL
  by an assigned coach; eligibility from `trial-eligibility.util.ts`. Follow TRIAL.md, not memory.
- Notifications: `NotificationsService.notify()` persists a row **and** pushes on the Socket.IO
  `/notifications` namespace; never one without the other. Telegram delivery goes through the
  `telegram-delivery` queue; outside production every message is routed to
  `TELEGRAM_ADMIN_CHAT_ID` with a `#DEV_ENV` tag (dropped if unset).
- Audit: every admin decision goes through `AuditService.record` with a key from
  `audit/audit.actions.ts`.
- Redis: cache through `RedisService`'s typed key helpers; read-through only — Postgres stays
  authoritative and a Redis outage degrades, never errors. Queues (`media-processing`, `trials`,
  `invitations`, `telegram-delivery`) run with `IDLE_TUNING` (long `drainDelay`) because Upstash
  bills per command. **Never leave a delayed or repeatable job parked in a queue** — BullMQ then
  polls every 10 s. Periodic work is a timer plus `RedisService.claimOnce` (`SET NX`).
- Errors: `NotFound` (no such resource), `Forbidden` (not yours), `BadRequest` (bad input or
  state), `Conflict` (duplicate / lost race), `Unauthorized` (who are you). Don't leak Prisma
  internals. Inside `$transaction`, never catch a unique violation and continue — Postgres has
  already aborted the transaction; use `createMany({ skipDuplicates })` or a conditional
  `updateMany` instead.
- JWT claims (roles, permissions) are a snapshot at login/refresh; a mid-session role change
  waits for the next refresh. Accepted; don't hit the DB per request to "fix" it.

## 4. API documentation is generated

`@nestjs/swagger` CLI plugin (`nest-cli.json`) builds the spec from controllers, DTOs and doc
comments. **After any route, DTO or response change run `pnpm docs:generate` and commit
`openapi.json`; `pnpm docs:check` fails when it is stale.** New `@ApiTags` must exist in
`src/swagger.ts` `API_TAGS`. Prisma enums in DTOs need `@ApiProperty({ enum, enumName })` or they
render as opaque objects. Generation runs in preview mode with no database.

## 5. Testing

Jest (`pnpm test`, specs beside the code as `*.spec.ts`, `rootDir: src`). Services are tested
with small hand-written Prisma/Redis fakes, pure utils directly. No e2e suite yet; if one is
added it lives in `test/` against the docker-compose Postgres, never the dev database. Keep the
suite green with every change; the number of specs is large, so run `npx jest <dir>` while
iterating and the full run before committing.

## 6. Never change without sign-off

- `SCOUT_LEVEL_TIERS`, `computeSuccessRate`, `computeScoutLevel` (README §1.5).
- Migration SQL under `prisma/migrations/` — new migrations only.
- `ROLES_KEY` / `PERMISSIONS_KEY` / `IS_PUBLIC_KEY` metadata strings — the guards look them up by
  exact value.
- `main.ts` `ValidationPipe` options.
- Argon2 for password/OTP hashing (README §1.3, §1.21).
- The `public/` vs `private/` storage split and the moderation gate on media.
